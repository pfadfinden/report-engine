# OAuth 2.1 audit of the frontend's OIDC integration

Audited against [draft-ietf-oauth-v2-1](https://datatracker.ietf.org/doc/draft-ietf-oauth-v2-1/) and
RFC 9207 (issuer identification), with Keycloak 26.7 as the authorization server. Line numbers refer
to the code as it was _before_ the hardening commits (`git show fa3db7e4:frontend/<file>`); the
"Status" column says what the commit series did about each finding.

## Deviations

| #   | Requirement                                       | Where                                                                                                                                                                                                                                                    | Finding                                                                                                                                                                                                                                                                                                                                                                                      | Status                                                                                                                                              |
| --- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | No credentials in logs (draft 7.5 / RFC 9700 4.x) | `express-app.ts:67` (morgan `:url`), `express-app.ts:175` (`http.path` of the error handler)                                                                                                                                                             | `GET /auth/callback?code=…&state=…` was written verbatim to the access log and, on a failed login, to the error telemetry. The code is single-use and PKCE-bound, `state` is the CSRF binding, but neither belongs in a log pipeline that is exported off-host.                                                                                                                              | Fixed: `auth/url-redaction.ts`, used by both.                                                                                                       |
| D2  | Authorization response must be single use         | `auth-router.ts:62-85`                                                                                                                                                                                                                                   | `session.pendingAuth` (state, nonce, PKCE verifier) was only discarded by the session regeneration on _success_. After a failed token exchange the same triple stayed valid for a replayed/retried callback.                                                                                                                                                                                 | Fixed: cleared before the code is exchanged.                                                                                                        |
| D3  | TLS everywhere outside local dev (draft 1.5, 7.1) | `oidc-client.ts:42` (`allowInsecureRequests` for any `http:` issuer, in any environment), `config.ts:146-147` (redirect and post-logout URIs unvalidated), `hitobito-roles.ts:70` (Hitobito access token sent to whatever scheme `HITOBITO_API_URL` has) | A production deployment with a mis-typed `http://` URL would run, silently, over plaintext.                                                                                                                                                                                                                                                                                                  | Fixed: `assertSecureAuthUrls` in `config.ts` refuses `http:` issuer / redirect / post-logout / Hitobito URLs when `NODE_ENV=production`.            |
| D4  | Exact redirect URI matching (draft 7.5.1)         | `config.ts:146`                                                                                                                                                                                                                                          | The value is a constant, never derived from the request (good), but nothing stopped a wildcard, query or fragment from being configured — none of which can ever be an exact match for what is registered at the AS.                                                                                                                                                                         | Fixed: same validation.                                                                                                                             |
| D5  | Issuer identification, RFC 9207 (mix-up defence)  | `auth-router.ts:75`                                                                                                                                                                                                                                      | `authorizationCodeGrant` does check `iss` (oauth4webapi `validateAuthResponse`) — but only _requires_ it when discovery says `authorization_response_iss_parameter_supported`. Against an AS that does not advertise this, a response without `iss` passes.                                                                                                                                  | Fixed: production refuses to start against such an AS (`assertIssuerCapabilities`); Keycloak 26.7 advertises it (`OIDCWellKnownProvider.java:228`). |
| D6  | Client authentication                             | `config.ts:111` (default `client_secret_basic`), `oidc-client.ts:28,65`, `hitobito-roles.ts`                                                                                                                                                             | A shared secret was the default and was threaded into `discovery()`.                                                                                                                                                                                                                                                                                                                         | Fixed in the _client authentication_ commit.                                                                                                        |

## Accepted / not a deviation

| Requirement                                   | Result                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authorization code grant only                 | Compliant. The only token request is `authorizationCodeGrant` (`auth-router.ts:75`); no implicit, ROPC or client-credentials code exists, and `response_type=code` is set by `buildAuthorizationUrl`. The AS-side switches are in README "Keycloak client configuration".                                                                                                                                                                                                                                             |
| PKCE `S256`, always                           | Compliant. `code_challenge_method` is the literal `'S256'` (`auth-router.ts:55`), a fresh verifier per login, the verifier never leaves the session (never in a URL). There is no code path that skips or downgrades it.                                                                                                                                                                                                                                                                                              |
| `state` and `nonce`                           | Compliant. Fresh per login, verified by `authorizationCodeGrant` (`expectedState`, `expectedNonce`).                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Exact `redirect_uri`                          | Compliant in the request (constant `config.redirectUri` at `auth-router.ts:51,72`), see D4 for the config side.                                                                                                                                                                                                                                                                                                                                                                                                       |
| Refresh tokens                                | Not used. No `offline_access`, no refresh grant; the `refresh_token` in the token response is never stored. Rotation/reuse handling is therefore not a client concern; the AS-side "Revoke refresh token" is still listed in the Keycloak settings so a token that never gets used also can't be rotated into a leak later.                                                                                                                                                                                           |
| Tokens kept server-side                       | Compliant. The session holds the principal and the ID token (needed as `id_token_hint`); the access token is used once for the broker call and dropped (`auth-router.ts:101-109`). The browser only gets the signed session-id cookie (`httpOnly`, `sameSite=lax`, `secure` in production, `express-session` config at `express-app.ts:134-137`). Helmet's default `Referrer-Policy: no-referrer` keeps the callback URL from leaking via `Referer`.                                                                  |
| ID token in a URL                             | **Open, accepted.** `/auth/logout` redirects to the end-session endpoint with `id_token_hint` in the query (`auth-router.ts:170`). That is how OIDC RP-Initiated Logout 1.0 works for a browser redirect, and an ID token is not an access/refresh token, but it does land in browser history and any proxy log in front of Keycloak. Dropping the hint (Keycloak then asks the user to confirm the logout) is the alternative if that matters more than the silent logout. Needs a product decision, so not changed. |
| Back-channel logout token in the request body | Compliant (POST body, verified in `logout-token.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
